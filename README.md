# 10 测试与验证模块

> 对应规划：阶段七（系统验证与交付定型）
> 第二轮新增：离线可跑的「决策仿真 + 无依赖测试运行器」，用于多变验证（无需 ESP32 编译器 / 无外网）。

## 一、功能
提供三类测试资产：
1. **接口联调客户端** `test_client.py`：向 `08_云端识别服务` 发送一张测试图（协议一致 JSON），打印识别结果，替代 Postman 做端云联通验证（需联网 + requests）。
2. **状态机单元测试** `test_fsm.py` + `fsm_model.py`：用 pytest 验证 06 模块的“三帧滑动窗口防抖”逻辑（含偶发误识别过滤、连续两帧切换、终止态转换等用例）。
3. **决策仿真 + 多变测试（离线可跑）**：
   - `sim_core_logic.py`：40 个场景仿真，用与 C++ 等价的 Python 逻辑复刻 06 核心决策（FSM 防抖、障碍距离扫描、调度灯色/优先级、离线阈值、RSSI→JPEG 质量、主循环时序、最坏上传 ≤3s、**雨天退化 17 项 + 天气模式一致性 + 云端天气字段→自动变档 5 项**）。
   - `test_simulation.py`：9 个多变仿真测试（FSM/障碍/调度/离线/JPEG/延迟预算）。
   - `test_rain.py`：17 个雨天/天气多变测试（盲道丢失/眩光误偏/误判终止/连续降级/弱网离线/湿滑 GAP/摄像头糊住/天气模式 + **云端天气字段自动变档 6 项**），用退化输入驱动现有决策逻辑验证雨天安全性。
   - `test_cloud_mock.py`：4 个云端「数据契约」测试（字段、限流、mock 风险分级、**weather 字段存在且合法**），用 `mock` 供应商在**无网络/无 API Key** 下端到端验证。
   - `protocol_fields.py`：与 `01/protocol.h` 的 `K_*` 键名一一对应的字段常量（含 `K_WEATHER` / `WEATHER_VALUES`），保证端/云/提示词三者契约一致。
   - `run_tests.py`：**无 pytest/无 requests 依赖**的轻量运行器，直接执行全部 `test_*.py` 中的测试函数，离线环境一键验证。
4. **测试计划** `test_plan.md`：覆盖功能/性能/稳定性/实地四类测试与验收口径。

## 二、作用
- 把阶段七“全维度测试验证、闭环问题、冻结版本”落到可执行步骤。
- `fsm_model.py` / `sim_core_logic.py` 是 06 算法的 Python 参考实现，保证无硬件也能验证核心逻辑正确性，并在本环境（无 ESP32 编译器）作为“按实际运行优化 + 多变验证”的主要手段。
- 仿真阶段发现的真实运行 Bug（障碍灯色被覆盖、离线阻塞 ~10s、HTTP 重试超时超验收、离线语音无节流、电量恒定、prompts 未打包）已全部回写真实 `.cpp/.py`。

## 三、拼接方法
1. 云端联调（需联网）：先启动 08 服务，再运行
   ```bash
   python test_client.py 测试图.jpg http://<服务器IP>:5000
   ```
   检查返回 JSON 字段与 `protocol.h` 一致。
2. 状态机单测：在本目录执行
   ```bash
   pip install pytest && pytest test_fsm.py -v
   ```
3. **离线全量验证（推荐，无需任何第三方库）**：在本目录执行
   ```bash
   python run_tests.py          # 35 个功能测试（FSM 单测 + 多变仿真 + 云端 mock 契约 + 雨天多变 + 云端天气变档），离线 35/35 PASS
   python sim_core_logic.py     # 40 个决策场景仿真（含雨天退化 17 项 + 天气模式闭环 + 云端天气自动变档），离线 40/40 PASS
   ```
4. 算法一致性：若修改 06 的防抖窗口（3 帧）或阈值，需同步更新 `fsm_model.py` / `sim_core_logic.py` 并补用例。
5. 现场实测按 `test_plan.md` 执行，结果归档到 TF 卡日志（由 07 主固件写入）并导出分析。
